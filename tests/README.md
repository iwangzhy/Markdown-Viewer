# PDF 导出回归验证

运行不依赖浏览器的测试：

```sh
node --test tests/pdf-pagination.test.cjs
```

分页坐标正确不代表绘制出的文字、SVG 一定完整，涉及导出逻辑或样式的修改还需要检查实际 PDF。

1. 启动静态服务器 `python3 -m http.server 8000`，用无已保存内容的浏览器会话打开首页，使用仓库自带示例导出 PDF。
2. 检查 `Multi-row Headers Support` 表格：`Document Type` 完整可见，合并单元格内部没有横线或背景遮挡；其他列保持对齐。
3. 检查 Mermaid 流程图：`Deploy` 节点的文字、右边框都可见；流程图、外框、标题和说明在同一页，不在上一页留下半截边框。
4. 检查时序图的最右列和底部节点。切换深色模式重复导出，检查图形和表格底色。
5. 用超过一页的中文段落、代码块和表格导出，检查页尾及下一页页首的文字完整，表格不出现一行占一页的情况。
6. 导出 `tests/fixtures/pdf-inline-code.md`：行尾代码换行后，前后中文完整可见，长行内代码和代码块中的长命令都在页宽内折行。

若页面仍出现旧版问题，先在浏览器网络面板核对实际加载的 `script.js`，不能只检查磁盘上的文件。Docker 部署更新需要重新构建镜像；HTML、JS、CSS 应返回 `Cache-Control: no-cache`。当前资源地址带有一次性的版本参数，用于绕过旧版本的一年强缓存。

图形本身能放入一页、但当前页剩余空间不足时，会整体移到下一页，因此上一页可能留白。超过一页的标题加图形组合会退回只保护图形，长段落和长代码块则允许在文字行间分页。
